# 7. 실험 결과

모든 수치는 결과 파일(`results/`)과 대조 검증된 값.

## 7.1 핵심 — 3단계 현실화 (full, LightGBM)
| 프로토콜 | Utt-EER | Range-EER |
|---|---:|---:|
| dev 내부분할 (낙관) | 0.84 | 7.69 |
| 정식 train→dev (in-domain) | 2.22 | 7.93 |
| **정식 train→eval (미학습, 최종)** | **13.88** | **24.60** |
> 낙관 0.84% → in-domain 2.22% → unseen 13.88%. eval 갭은 미학습 공격 탓이며 정상.
> **13.88% / 24.60%가 신뢰 수치.** (동일 모델, 평가 프로토콜만 변경)

## 7.4 특징 기여도 (정식 train→dev)
| 제거 | ΔUtt-EER | ΔRange-EER | 중요도(gain) |
|---|---:|---:|---:|
| full 기준 | 2.22 | 8.04 | - |
| −stft | +2.49 | +2.32 | **61.9%** |
| −lfcc | +0.21 | +0.15 | 22.7% |
| −phase | +0.11 | +0.68 | 7.1% |
| −disc | +0.09 | −0.04 | 8.3% |
> STFT가 일꾼(중요도 62%). 중요도≠한계기여: LFCC는 중요도 23%지만 제거 영향 +0.2p
> (STFT와 중복=magnitude). phase는 국소화에 기여(제거 시 Range +0.68).

## 7.8 개선 시도 (전부 정직한 negative)
- **후처리(평활)**: gaussian-1.0으로 dev Range-EER 7.93→**6.38**(개선), eval 25.6→25.0(무효).
- **데이터 증강(train)**: eval Utt 13.88→**15.54(악화)**. 원인 = 가짜 단서 희석
  (FRR 0.139→0.181, 가짜 점수 0.945→0.935, 클래스 분리도 0.241→0.222↓).
- **경계 가중(sample_weight)**: dev Range 6.42→8.27, eval 24.89→26.27 **악화**
  (경계 윈도우 라벨 노이즈).
> 입력·출력·목표 다 손봐도 unseen 안 됨 → **병목은 표현(feature)**.

## 7.9 CQCC shortcut 규명 (엄밀성)
| 측정 | full | full+cqcc | 차이 |
|---|---:|---:|---|
| 발화 EER(eval, 오염) | 13.88 | 2.90 | −11.0 (대부분 shortcut) |
| window-EER 순수(부분발화 프레임) | 21.01 | 19.42 | −1.6 (진짜 기여) |
| Range-EER(eval) | 24.89 | 23.77 | −1.1 (진짜) |
- cqcc 단독 eval Utt-EER 3.29%. 조작비율별 cqcc 탐지율 0–10%=**78.5%**(full 58.9%).
> 거의 진짜인 파일(0–10%)도 78.5%로 탐지 = '내용' 아닌 **파일 전역 가공 시그니처**(shortcut).
> 5배 개선은 dataset shortcut, **순수 기여는 ~1.5pt** → 채택 안 함.
> 방법론: 같은 파일 내 프레임 판별(국소화)은 shortcut-free → 순수 기여를 **분리 측정**.
